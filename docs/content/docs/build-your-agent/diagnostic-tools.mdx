---
title: Diagnostic Tools
description: The shared diagnostic surface for DeepAgent, native Codex and custom agents.
---

Use the episode's MCP endpoint to investigate the initial Pingmesh symptoms. The registry provides live device reads, historical telemetry, and active probes.

| Tool | Evidence |
|---|---|
| `get_topology()` | Devices, client attachments, and fabric links. |
| `get_device_config(device)`, `get_bgp_rib(device)` | Running configuration and BGP routes. |
| `get_device_logs(device)`, `get_interface_metrics(device, interface)` | Historical log events and interface counters. |
| `get_bgp_neighbors(device)` | Peer inventory and current session states. |
| `get_pingmesh_hotspots()` | Leaf/edge pairs with the largest observed impairments. |
| `ping_test` | Live reachability and RTT between the selected endpoints. |
| `get_device_status(device)` | Actual node running/accessibility, supported bgpd/zebra service states and collection time. Unavailable service data is reported explicitly, without an inferred fault label. |
| `get_route_table(device, view="kernel", prefix=...)` | Actual kernel IPv4 FIB, including multipath next hops. The default `view="frr"` remains the FRR route table. |
| `get_bgp_neighbor(device, peer, view="advertised_routes", prefix=...)` | Live advertised routes for one peer; optional exact-prefix filter. The default `view="detail"` retains session details. |
| `get_device_interfaces(device, interface=...)` | Interface state/counters and actual IPv4 addresses/masks, optionally filtered by interface (including aliases). Traffic-control injection configuration is not exposed. |
| `get_device_acl(device)` | SONiC table/rule match fields, port/stage attachment and iptables FORWARD counters, including input/output interfaces. |
| `query_bgp_events(event_type="prefix_count")` | Prefix-count changes from the existing BGP collector. Session mode reports adjacency changes. Collection gaps are explicit, and failed collection never becomes prefix count zero. |
| `get_pingmesh_summary(src_client=..., dst_client=...)` | Optional client filters over the existing aggregated output. |
| `traceroute(src, dst_ip, max_hops=...)` | Default 8, maximum 32 hops, bounded by the diagnostic session deadline. |

A count decrease is a clue. Confirm the specific prefix through RIB, advertised
routes and kernel FIB. A missing container, a stopped bgpd and a down BGP peer
are separate observations; avoid treating collection failure as routing failure.

Pingmesh queries select their time range in this order: explicit `start_time`/`end_time`,
current toolkit episode window, context file, environment times, rolling
fallback. `get_pingmesh_hotspots` remains aggregated by leaf/edge pair. Filtering
summary clients does not change the hotspot granularity.

Device snapshots carry `collected_at`. Logs and interface telemetry use the
current episode window by default and filter by topology identity; responses
include `time_scope`. A live fallback snapshot is explicitly separate from
historical telemetry. Periodic faults can be healthy at the instant of a live
query: inspect the full historical window before concluding network health.

BGP tool parameters are enumerated in the MCP schema. For `get_bgp_neighbor`,
use `view="detail"` or `view="advertised_routes"`; `advertised-routes` and
`advertised` are accepted aliases for the latter. Received routes are not
supported. `prefix` applies only to advertised routes and matches exactly.
For `get_bgp_neighbors`, use `format="structured"`, `"raw"`, or `"both"`;
`"json"` aliases `"structured"`. Invalid view/format values return argument
guidance; collection failures remain redacted as `Observation unavailable`.
