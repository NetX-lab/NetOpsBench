## NetOpsBench v0.2.0 release validation

This 2026-08 release snapshot used `minimal-deepagent` with `deepseek-v4-pro`, thinking disabled, temperature 0, and two runtime workers for the XS–Large campaigns. All 109 cases completed under the NetOpsBench v0.2.0 runtime, Rust client-agent, traffic, and Pingmesh contract.

![DeepSeek 0.2 release quality by scale](/assets/benchmark/fig_deepseek_v02_quality.png)

Across all scales:

- Primary reward was **72.9%** (`79.5 / 109`).
- Verdict accuracy was **80.7%** (`88 / 109`), including **13 / 13** healthy cases and no false positive.
- The Agent detected **75 / 96** positive cases (**78.1%**).
- Device localization was **69 / 96** (**71.9%**) over all positive cases and **69 / 75** (**92.0%**) conditional on the Agent reporting a fault.
- Interface localization was **26 / 56** applicable cases (**46.4%**); fault-type accuracy was **43 / 96** (**44.8%**).
- There were 13 inconclusive traces and 8 positive cases incorrectly reported as healthy.

### Detector and runtime validity

All **109 / 109** cases were valid, had successful Pingmesh queries, complete coverage, successful injection/recovery, and successful cleanup. All 13 healthy cases had zero formal Pingmesh anomalies. There were no local DF/PMTU probe errors and no unexpected latency anomalies outside `high_latency`.

![DeepSeek verdicts versus formal Pingmesh signals](/assets/benchmark/fig_deepseek_v02_fault_signals.png)

The fault-family view separates observation quality from Agent behavior:

- `high_latency`, `mtu_mismatch`, `packet_loss`, and `packet_corruption` had formal Pingmesh evidence in every case, but the Agent's correct-verdict counts were only `2/8`, `4/8`, `3/8`, and `4/8`.
- `bgp_neighbor_misconfig` produced no endpoint Pingmesh anomaly in all eight redundancy-preserving cases, as expected, while the Agent diagnosed all eight through BGP and device telemetry.
- Access link-down and leaf device-down blast radii matched the topology exactly. On Large, access link-down affected `126 / 126` expected directed client paths and leaf device-down affected `492 / 492`.
- Six Large loss/flapping cases contained nine isolated DF-only MTU suspects, at most `2 / 4032` paths in one case. They were absent from healthy cases and are much smaller than true MTU faults (`326–378 / 4032` paths), so they are retained as low-level correlated impairment evidence rather than relabeled as MTU root causes.

The dominant limitation in this snapshot is therefore Agent detection and termination, not infrastructure validity or missing Pingmesh signal.

### Large-topology observation validity

- Xlarge had `70 / 70` case-valid results, complete Pingmesh coverage, successful cleanup, zero local probe-error cases, and four healthy cases with zero formal anomalies.
- K=8 had `70 / 70` case-valid results, complete Pingmesh coverage, successful cleanup, zero local probe-error cases, and four healthy cases with zero formal anomalies.
- K=12 had `70 / 70` operationally valid observations after the access-link fix, complete coverage, zero local probe-error cases, and four healthy cases with zero formal anomalies.
- BGP neighbor misconfiguration generally preserved endpoint forwarding under ECMP. All Xlarge and K=12 BGP cases had zero endpoint anomaly; four of six K=8 cases had zero and two contained one isolated packet-loss event. BGP/device telemetry still exposed every control-plane fault.
- K=8 high-latency cases produced `586–698` formal latency paths, MTU cases `585–738` DF-loss paths, packet-loss cases `102–124` loss paths, packet-corruption cases `61–82` loss paths, and blackholes `8–42` affected paths. These are well separated from the four clean healthy cases.
- Xlarge high-latency cases produced `12–17` formal latency paths and MTU cases produced `57–97` DF-loss paths. K=12 high-latency cases produced `169–242` latency paths and MTU cases produced `247–302` DF-loss paths.
- Upper-fabric link-down cases can have zero or only a few endpoint anomalies when ECMP reroutes successfully. Access link-down retained the expected endpoint-scale blast radius: `254` directed paths on Xlarge and K=8, and approximately `286` on K=12.

Xlarge fabric link-down and link-flapping therefore should not be read as detector misses solely because the endpoint anomaly count is zero. A physical member can fail, interface/BGP telemetry can record the transition, and ECMP can reconverge before enough full-window probes are lost to form a formal endpoint anomaly. Packet corruption is similarly hash-selective: the impairment is applied to one egress member, so only probe flows mapped to that member provide loss evidence.

The Agent failures on these data-plane cases show a different limitation. Several trajectories mixed episode-window evidence with recovered current state, used one successful live ping to dismiss historical multi-hash Pingmesh loss, or searched many edge devices without a disciplined transit-attribution strategy. Some then reached the graph recursion limit. The benchmark preserves both evidence surfaces deliberately: episode-scoped telemetry establishes what happened during the fault, while live probes describe the network at diagnosis time and cannot erase the historical observation.
