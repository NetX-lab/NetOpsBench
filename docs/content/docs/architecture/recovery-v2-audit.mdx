## 起点与执行链

本轮起点为 `bf09430`。保留用户目录 `presentations/`，不修改冻结场景文件。

```text
SDK / CLI：新建 v2，或显式迁移旧场景
  → 部署前验证 recovery_policy
  → session 按 runtime 所有权和 keep_runtime 传递销毁意图
  → IncidentEngine / ExecutorIncidentBackend
      → 有界健康基线：10 次 / 600 秒 / 环境身份
      → 校准（需要时）→ 注入 → 观察 → 诊断
      → 恢复回调及回读 → 两轮全设备状态检查
      → 状态通过：恢复原基线复用资格
      → 异常后恢复：完整校准；残留或证据不足：失败隔离
  → 保留或外部 runtime：末尾校准
  → 确定销毁：记录跳过末尾窗口，执行并验证销毁
```

完整校准仍是公共执行核心的一项内部能力。`full_window` 只作为私有报告的
验证等级保留，不再是运行模式；Pingmesh 异常持续性中的同名值语义不同，也保留。

## 删除依据

| 删除/收敛项 | 原调用者及输入不变量 | 保留的行为与验证 |
|---|---|---|
| 旧恢复模式与版本兼容执行分支 | 所有执行入口现在要求 v2；旧配置在部署或获取租约前拒绝 | 显式迁移、SDK/CLI、旧报告读取测试 |
| `post_recovery_wait_seconds` 及多层参数传递 | 只供旧模式在撤销后固定等待；新流程按条件收敛 | 共享 deadline、收敛重试、双轮状态验证测试 |
| 单次消费基线、独立 epoch 刷新入口 | 所有案例使用有次数和年龄上限的已验证基线 | 第 10/11 次、600 秒、失败失效和环境变化测试 |
| prepare 内独立基线采集/查询分支 | 缺少可复用基线时必须调用统一校准入口 | 完整窗口只采一次；不健康及不完整窗口拒绝执行 |
| `wait_and_observe` 及 executor 转发 | 唯一生产调用者是已删除的旧恢复窗口分支 | 查询时间范围和 deadline 测试迁到采集/分析边界；计时迁到校准入口 |
| 健康案例观察窗口候选与发布回退 | 新流程只有完整校准可以更新健康基线；每例状态恢复不刷新窗口 | 健康案例仍观察和诊断；绝对健康证据缺失不能通过校准 |
| 旧模式末尾再次比较旧 FIB 快照 | 新流程已在两轮实时采集中比较 FIB | 邻居身份、下一跳和再次变化的行为测试保留 |
| `valid_window` 纯转发 | 生产代码没有调用者，测试直接使用 `window_error` | 窗口长度、时间边界及错误原因测试保留 |

故障注册表、恢复回调、自定义 agent/evaluator、容器资源脚本、遥测 fallback、
接口别名和历史报告解析不属于本轮废弃项。未将“无直接 import”视为不可达证明。
未实施 Docker 同阶段采集去重；本轮性能变化来自校准调度策略。

## 单列行为修复

完整校准失败后记录失败状态，后续状态检查不能重新授予健康基线复用资格。
校准必须提供绝对不可达、丢包和 MTU 健康证据；缺失不能按零处理。错误窗口
保存在私有阶段记录中，不进入 agent 输入。对应负向测试检查失败隔离与证据保留。

验收脚本的影子校准恢复原基线、消费次数和校准状态，避免影子窗口延长正式
基线寿命；影子失败仍使验收失败。首次实测发现脚本残留的 `mode` 读取，修复后
重新运行；失败试跑记录保留，环境已销毁，不计作通过验收。

取消边界修复：session 现在也会在 `KeyboardInterrupt` 等中断后执行既定销毁，
并分别保留执行中断和清理错误，避免跳过末尾窗口后遗漏销毁。该路径以生命周期
回归验证；真实故障验收驱动直接调用 executor，不经过 session 编排层。

## 兼容与迁移

公开 `RecoveryPolicy` 名称保留，删除 `mode` 参数，版本必须为 2。
默认最大使用次数为 10、最大窗口年龄为 600 秒。旧场景显式迁移：

```bash
netopsbench scenario migrate SOURCE --out NEW_DIRECTORY
```

输出新的 scenario 摘要及迁移 campaign 身份，保留案例 ID、故障参数和实验配置。
`migration.json` 及各场景的 `recovery_migration` 记录源文件摘要和原场景摘要。
目标必须不存在且不能位于源目录内；读取和验证全部场景后才发布输出。
历史报告不需要迁移；冻结场景不做运行时隐式覆盖。迁移针对现有单 episode
场景，更早的 multi-episode 格式仍需重新生成。

## 性能对照（v2，2026-11-05）
